1. 运行通知开关：设置页「运行中的通知栏提醒」。开=前台服务+通知；关=startForeground 一次后立即 stopForeground(STOP_FOREGROUND_REMOVE)，通知记录数为 0（实测 NotificationRecord=0、isForeground=false、服务进程与 4 个 bot 仍在）。

4. 版本号：1.0.0 / 1000（关于页同步）。

## 三、功能清单（全量）

### 运行与保活
- 三种模式：普通 / ADB(Shizuku) / root；bot 运行内核相同，差别只在保活权限。
- 状态页 hero 胶囊：bot 真在线才显示模式名，否则「未启动」。
- Shizuku 主动申请权限（ShizukuShell.requestPermission + 一次性监听）。

### 群聊 / 私聊
- fail-closed 闸门：mentions[].is_you 权威判定 → 作者三信号 → 回声哈希 → 限流 6/60s → 熔断 12/60s 静音 5 分钟；判不出 @ 就不回。
- 回复清洗 + 角色硬规则（去 Markdown/代码块/路径，1~3 句、≤120 字）。
- 本地指令 #时间（不走模型）；system prompt 注入当前时间。
- 识图：附件下载（≤10MB）→ base64 → 视觉模型；识图模型留空沿用主模型；失败把响应体写日志并按纯文本继续。

### 人格与文案
- 内置：奥黛塔 / 哥伦比娅 / 桑多涅 / 沃雅妮莎 / 猫娘 / 鲸鱼娘。
- 导入：.md/.txt ≤256KB，落 files/personas；管理面板只列导入项，内置不可删。
- 称呼（master/others）与定时问候按 bot 独立配置。

### 定时问候
- 每 bot：enabled + targets{owner,groups} + slots[{name,at,window_min,lines,disabled}]。
- 窗口内随机时刻，种子=(appid,日期,时段名)：同 bot 当天固定、不同 bot 错开；每「时段|目标」每天一次。
- 内置人格内容由代码给定（不可改），时刻/窗口/开关可改；自定义人格内容可编辑。

### 记忆
- 本机 memory.json（p/g 键）；多选（可跨 bot）、顶部固定选择条、10 秒撤销、下拉刷新、清空识图缓存；删除/撤销后自动重启对应 bot。

### 界面
- MiuiX 单主题、自适应图标、深色、二级页统一 SecondaryTopBar。
- 关于页：版本/构建时间/机型/Android/Python/Chaquopy + 四项开源致谢。
- 首次引导（正式包启用）：欢迎 → 模式 → 真检测（Shizuku/root/白名单）+ 通知权限 → 模型（可跳过）→ 完成。
- 后台不显示任务卡片（excludeFromRecents）。

## 五、已知边界

1. 「关通知」= 服务退出前台态（stopForeground REMOVE），通知确实消失；代价是失去前台保护、被系统回收概率上升（本机 root + 电池白名单下 4 bot 运行正常）。若要保持前台保护，就只能保留通知。
2. Shizuku 系统授权弹窗未在真机实测（本机 Shizuku 服务不常驻）。
3. 群发问候与 #时间 的群内链路仅 stub 证据（禁止执行者向真实群发消息）。
4. 识图只识别第一张图，其余附件忽略；>10MB 跳过。
5. 回复判定（judge）只在群里触发，私聊不经过判定。
6. 从旧版本升级且无 onboarded 标记的用户会看到一次引导。
7. 模块模式与面板 API 已彻底删除；Material 主题代码保留但无入口。
8. 旧的「定时消息」不再执行（tasks.json 保留），统一由定时问候承担。

## 七、变更记录（相对 1.0.0）

### 1. ADB(Shizuku) 模式真正可用
- 修 3 个缺陷：`UserService` 必须直接是 `IUserService.Stub`（原来继承 Service 导致 ClassCastException）；binder 异步下发需等回调（≤5s）；Shizuku 服务被 SIGKILL 后 `bound` 假阳性改判 `bound && pingBinder`。
- Manifest 补 `moe.shizuku.manager.permission.API_V23` 与 `<queries>`。
- 设备侧已升级到 **Shizuku 13.7.0-thedjchi**（官方 13.6 及以下在 Android 17 上服务会自杀：`AbstractMethodError: IProcessObserver.onProcessStarted`）。
- 注意：设备上装的是**重签版**（原版 APK 把 `lib*.so` 压缩，服务 `dlopen` 失败，已用 `zip -0` 重打包并以 CN=AndbnA 签名）；如要用作者原版需先卸载。
- 启动命令（13.7）：`adb shell <apk目录>/lib/arm64/libshizuku.so`。

### 2. 自动拉回（看门狗）
- 进程外常驻 sh 脚本，ADB 走 Shizuku shell 通道、root 走 su，同一份脚本；文件通信目录 `getExternalFilesDir()/autopull/`（state/hb/pid/off/pause/log）。
- `nohup setsid` detach（PPID=1），父 shell 退出不影响；存活判定三重：`kill -0` + 心跳 ≤120s + state=running，任一失败即清状态并重启脚本。
- 周期 60s，10 分钟最多 3 次，超限「已达上限，暂停」；连续 2 周期稳定则重置计数。
- 「停止全部」写 `user_stopped=true` + pause 文件，看门狗不拉回；「启动全部」清除。
- 设置页新增「自动拉回」开关（仅 ADB/root 模式显示，默认开）。

### 3. 运行通知开关
- 设置页「运行中的通知栏提醒」：开=前台服务+通知（IMPORTANCE_LOW）；关=`startForeground` 一次后立即 `stopForeground(STOP_FOREGROUND_REMOVE)`，通知记录数为 0，服务退出前台态（被回收概率上升）。
- 引导第 3 步含通知权限（被动申请，拒绝后给用途说明 + 跳系统设置）。

### 4. 其它
- 问候改为每 bot 独立 + 时段内随机错开发送（`greetings.json`，内置人格内容由代码给定、时刻可改、时段可关）。
- 称呼按 owner openid 判定主人/其他人（`phrases.json` 两键）。
- 删除重复入口：Bot 编辑页「定时消息」下线（`tasks.json` 保留但不执行）、Bot 页动作行「添加」、设置页「问候时段」；人格页只留导入/管理。
- 关于页致谢 5 条（含 DGP-Studio/Genshin.Skill、linsport/dsh-whale-persona、JetBrains/compose-multiplatform）。
- 设备上旧 root 循环 `/data/adb/service.d/andbna_qbot.sh` 已改名 `.disabled`。

### 5. 已知边界补充
- 看门狗拉起延迟最长 60s（脚本周期）；若要更快可把周期降到 30s（心跳容忍度随之 60s）。
- Shizuku 服务重启后只在新进程下发 binder，需重启 App 才重新绑定（App 内有小字提示）。
- 设备 `ps` 会漏报进程，存活判定一律以 `kill -0` 为准。

## 八、1.0.1（1010）

- 版本号 1.0.1 / 1010。
- 看门狗周期保持 60s（省电取向，代价是拉起延迟最坏 60s）。
- 防抖上限沿用脚本内实现：10 分钟内最多 3 次，第 4 次判定记「已达上限，暂停」并退出，App 不会重启它（等用户点「启动全部」解除）。比「4 次」更保守一档；如需改成 4 次只改 PullBack.kt:37 的 MAX_HITS。
