## 五、已知边界

1. 「关通知」= 服务退出前台态（stopForeground REMOVE），通知确实消失；代价是失去前台保护、被系统回收概率上升（本机 root + 电池白名单下 4 bot 运行正常）。若要保持前台保护，就只能保留通知。
2. Shizuku 系统授权弹窗未在真机实测（本机 Shizuku 服务不常驻）。
3. 群发问候与 #时间 的群内链路仅 stub 证据（禁止执行者向真实群发消息）。
4. 识图只识别第一张图，其余附件忽略；>10MB 跳过。
5. 回复判定（judge）只在群里触发，私聊不经过判定。
6. 从旧版本升级且无 onboarded 标记的用户会看到一次引导。
7. 模块模式与面板 API 已彻底删除；Material 主题代码保留但无入口。
8. 旧的「定时消息」不再执行（tasks.json 保留），统一由定时问候承担。

## 七、变更记录（相对 1.0.0）

### 1. ADB(Shizuku) 模式真正可用
- 修 3 个缺陷：`UserService` 必须直接是 `IUserService.Stub`（原来继承 Service 导致 ClassCastException）；binder 异步下发需等回调（≤5s）；Shizuku 服务被 SIGKILL 后 `bound` 假阳性改判 `bound && pingBinder`。
- Manifest 补 `moe.shizuku.manager.permission.API_V23` 与 `<queries>`。
- 设备侧已升级到 **Shizuku 13.7.0-thedjchi**（官方 13.6 及以下在 Android 17 上服务会自杀：`AbstractMethodError: IProcessObserver.onProcessStarted`）。
- 注意：设备上装的是**重签版**（原版 APK 把 `lib*.so` 压缩，服务 `dlopen` 失败，已用 `zip -0` 重打包并以 CN=AndbnA 签名）；如要用作者原版需先卸载。
- 启动命令（13.7）：`adb shell <apk目录>/lib/arm64/libshizuku.so`。

### 2. 自动拉回（看门狗）
- 进程外常驻 sh 脚本，ADB 走 Shizuku shell 通道、root 走 su，同一份脚本；文件通信目录 `getExternalFilesDir()/autopull/`（state/hb/pid/off/pause/log）。
- `nohup setsid` detach（PPID=1），父 shell 退出不影响；存活判定三重：`kill -0` + 心跳 ≤120s + state=running，任一失败即清状态并重启脚本。
- 周期 60s，10 分钟最多 3 次，超限「已达上限，暂停」；连续 2 周期稳定则重置计数。
- 「停止全部」写 `user_stopped=true` + pause 文件，看门狗不拉回；「启动全部」清除。
- 设置页新增「自动拉回」开关（仅 ADB/root 模式显示，默认开）。

### 3. 运行通知开关
- 设置页「运行中的通知栏提醒」：开=前台服务+通知（IMPORTANCE_LOW）；关=`startForeground` 一次后立即 `stopForeground(STOP_FOREGROUND_REMOVE)`，通知记录数为 0，服务退出前台态（被回收概率上升）。
- 引导第 3 步含通知权限（被动申请，拒绝后给用途说明 + 跳系统设置）。

### 4. 其它
- 问候改为每 bot 独立 + 时段内随机错开发送（`greetings.json`，内置人格内容由代码给定、时刻可改、时段可关）。
- 称呼按 owner openid 判定主人/其他人（`phrases.json` 两键）。
- 删除重复入口：Bot 编辑页「定时消息」下线（`tasks.json` 保留但不执行）、Bot 页动作行「添加」、设置页「问候时段」；人格页只留导入/管理。
- 关于页致谢 5 条（含 DGP-Studio/Genshin.Skill、linsport/dsh-whale-persona、JetBrains/compose-multiplatform）。
- 设备上旧 root 循环 `/data/adb/service.d/andbna_qbot.sh` 已改名 `.disabled`。

### 5. 已知边界补充
- 看门狗拉起延迟最长 60s（脚本周期）；若要更快可把周期降到 30s（心跳容忍度随之 60s）。
- Shizuku 服务重启后只在新进程下发 binder，需重启 App 才重新绑定（App 内有小字提示）。
- 设备 `ps` 会漏报进程，存活判定一律以 `kill -0` 为准。

## 九、1.0.2（1020）

### 1. 状态页「资源占用」卡（root / ADB 显示，普通模式隐藏）
- 内存：ActivityManager.MemoryInfo（百分比 + 已用/总量）；
- CPU：两次采样 /proc/stat（间隔 1s）算整机百分比，Android 17 直读被拦时走一次特权 shell（root=su / ADB=Shizuku）；都读不到才退回本应用 CPU 并在 UI 标注；
- 机器人占用：/proc/self/smaps_rollup 的 Pss；代理占用：扫 /proc 汇总 <包名>:shell 与 watchdog.sh 的 RSS；
- 刷新 5 秒，离开页面即停采（无常驻线程）；进度条 gapSize=0、drawStopIndicator={}，无端点圆点。

### 2. hero 卡片
- 副标题不再重复 bot 数量，改为**运行时长**：不到 1 分钟 / N 分钟 / N 小时 / N 天；
- 修「计时一直不涨」的真因：原先只要状态文本瞬间不含「已上线」就清零计时，现改为**服务真停了才清零**；
- 新增「启动中 · 正在拉起 Python 与 N 个 bot…」即时反馈（点按钮 400ms 内生效，自动拉起同样生效），过渡期轮询 800ms。

### 3. 状态页精简
- 删掉信息卡里重复的「运行模式」行与「启用 bot」行（hero 上已有）；
- 自检从一大段依赖清单改为一行结论（完整清单只进日志，30 秒自动收起）。

### 4. 思考强度（可选，平台无关）
- 模型配置页用弹出选择器（与人格选择器同款）：不指定 / None / Minimal / Low / Medium / High / Xhigh / Ultra / Max / 自定义…；
- **显示大写、发送小写**：DeepSeek 官方只认小写（实测选 Low 发送会 422，发送 low 才 200）；自定义值原样透传；
- 留空 = 请求体里**没有** reasoning_effort 字段（最安全）；判定/回复/识图三条请求体共用同一拼装逻辑；
- 「验证思考强度」按钮：发最小请求，返回三态（支持 200 / 不支持 4xx + 响应片段 / 失败），完整响应进日志。

### 5. Shizuku 泄漏根治（重要）
- 真凶是**我们自己的 Shizuku UserService 进程**（app_process + framework + 本 APK，约 125 MB）：每次 bind 起一个，Shizuku 13.7 在客户端进程死后**不回收**，于是变 PPID=1 孤儿；
- 修法：root 模式 bind 硬门（直接 return）、bind 幂等、unbind(reason)、invalidate 真解绑、BotService.onDestroy 解绑、**ADB 模式懒绑定**（只有真要跑 shell 才 bind）；
- 兜底 ShellJanitor：App 起一次 + 每 2 分钟扫 /proc，命中的条件为 cmdline 含 <包名>:shell、PPID=1、存活 > 300s、且 5 分钟内没有活跃子孙，命中就 kill -9 并记日志；
- 实测：ADB 反复重启 5 次 → :shell 计数 1,1,1,1,1（改前 1,2,3,4,5）；root 模式 10 分钟 0,0,0,0…；切出 ADB 有解绑日志；孤儿在下一次扫描内被清（≤2 分钟）；
- **坑**：unbindUserService 的 remove 必须为 false。remove=true 会把 UserService 从 Shizuku 注册里摘掉，之后再也 bind 不上（实测切 ADB 直接回滚 root）。

### 6. 测试纪律（护屏）
- 设备屏幕**默认熄屏**；不要长时间亮屏（防烧屏）；
- 熄屏时 adb screencap 得到全黑图（实测亮度 0），**截图必须走投屏抽帧**：

## 十、1.0.3（1030）：修「已运行 N 分钟」不刷新

现象：hero 的「已运行」长时间停在「不到 1 分钟」。

两个原因，都修了：
1) 计时来源于 Compose 的 remember 状态，切页/重组就丢 → 改为从落盘的 svc_started_at（BotService.onCreate 写入）读，再用进程启动时长（Process.getStartElapsedRealtime）兜底；
2) 更关键：Compose 只在状态值变化时重组，而 svcSince 每轮读到的都是同一个值 → 没有状态变化 → 文案根本不重绘。改为每轮轮询写入 tick，hero 依赖 tick，于是每 3 秒必重绘。

实测（真机 1.0.3）：T+25s 显示「已运行 不到 1 分钟」→ T+95s 显示「已运行 1 分钟」，跨分钟自动跳变。

附注：熄屏时界面不重绘（没有帧就没有重组），此时读数看起来停住属正常；亮屏即刷新。
