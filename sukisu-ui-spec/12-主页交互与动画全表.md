# 12 · 主页交互与动画全表（SukiSU Ultra v4.2.1 / Miuix 0.9.4）

> **本文定位**：横向总表。单卡的七项规格不在这里（见 **10-主页.md**），hero 弹层与 Tilt 的全套数值不在这里（见 **15-hero交互与动画.md**）。本文只回答三件事：
> ① 主页上到底哪些节点能点、点完去哪、按下时给了什么反馈；
> ② `HomeUiState` 在 H1（工作中）/ H2（未安装）/ H3（不支持）之间切换**有没有过渡动画**——给定论；
> ③ 除按压反馈外，主页还有哪些**真**动画、哪些地方看着像动画其实根本没动。

路径约定同 10/15：App 代码 `ui/screen/home/HomeMiuix.kt:282` 的相对根是 `manager/app/src/main/java/com/sukisu/ultra/`；库代码前缀 `miuix:` 相对解包树 `miuix-src/src/commonMain/top/yukonga/miuix/kmp/`。

## 0. 结论速览（三句话）

1. **可点入口共 11 处**（其中 2 处为条件出现）：3 张带动作的 WarningCard、hero 三分支 + 1 个内嵌越狱按钮、支持链接 2 行、顶栏 ×、重启弹层 N 条；此外**还有 4 张 WarningCard 结构上可点、点了什么都不做**（但按下会 Sink 缩放）。
2. **状态切换无任何过渡动画**：`StatusCard` 用裸 `when` 直接换分支，整条重组的路径上没有 `AnimatedContent` / `Crossfade` / `animate*AsState` / `animateItem` / `updateTransition`（grep 证据见 §3）——H1→H2→H3 是**硬切**，卡底色、卡高、图标全部瞬变。
3. **全页唯一的 Compose 动画是更新横幅的 `AnimatedVisibility`**（`HomeMiuix.kt:202-206`，四个 builder 全部无参 = 全用库默认）；其余"会动"的东西都来自库内三条机制：Tilt/Sink 按压反馈、顶栏大标题折叠、越界回弹弹簧。

**三条判读要点（容易被写错的地方）**

1. **`WarningCard` 一律 Sink，恒可点**：组件把 `onClick = { onClick?.invoke() }` 无条件传给 `Card`（`ui/component/miuix/WarningCard.kt:32`），所以"没动作"的那 4 张卡**仍会响应按下并缩到 0.94**（`miuix:utils/PressFeedback.kt:31-34`）。只有水波被关掉（`showIndication = onClick != null`，`:37`）。还原时若把这 4 张卡做成"完全没反应"，观感会和原版不同。
2. **长按在整个主页面上不存在**：对 `ui/screen/home/`、`RebootListPopupMiuix.kt`、`DropdownItem.kt`、`WarningCard.kt` 同时 grep `onLongPress|onLongClick|combinedClickable` → **0 命中**（exit=1）。顶栏 × 的 `holdDownState` 是"外部状态驱动的持续按下外观"，不是长按（`miuix:basic/IconButton.kt:53-58`）。
3. **hero 三分支的点击动作完全相同**，差别只在**可点条件**与**卡片几何**：都是 `onInstallClick()`，都被 `!isLateLoadMode` 关掉。H3 明明是"不支持"也照样跳安装页——这不是 bug，是刻意引导（`HomeMiuix.kt:411-415`）。

## 2. 三处 `PressFeedbackType.Tilt` 对照（:288 / :382 / :417）

三处**同一个库实现、同一套数值**（`tiltAmount`、弹簧、轴心规则、`cameraDistance`）——差异全部来自**它们挂在哪张卡上**以及**卡里有没有别的手势节点**。

| 维度 | ① `HomeMiuix.kt:288`（H1 工作中） | ② `HomeMiuix.kt:382`（H2 未安装） | ③ `HomeMiuix.kt:417`（H3 不支持） |
|---|---|---|---|
| 卡片本体 | `Card(fillMaxWidth, colors = 绿/动态 secondaryContainer)` `:273-281` | `Card(Modifier.weight(1f))`，不染色 `:374-375` | `Card` 无 modifier，不染色 `:410` |
| 内容根 | `Box`（内含 110dp 背景图标 + 左下模式字 + 左上标题） `:290-367` | `BasicComponent`（标题/副标题/左图标/右 `endActions`） `:384-404` | `BasicComponent`（标题/副标题/左图标） `:419-430` |
| 卡高（决定 8° 的视觉幅度） | 由内容撑开，`height(IntrinsicSize.Min)` 的外层 Row `:267-270` | `BasicComponent` 最小 **56dp** + `insideMargin` 16dp `miuix:basic/Component.kt:161`、`:164` | 同 H2（56dp 起） |
| `showIndication` | `!state.isLateLoadMode` | 同 | 同 |
| 水波颜色轨道 | `MiuixIndication(color = onBackground)`，按下 **+10% alpha**，进 `folmeSpring(1.0, 0.2)` / 出 `folmeSpring(0.95, 0.35)`（**三段共用，数值见 15 §2.4**） | 同 | 同 |
| 卡内嵌套手势 | **无**（图标是纯 `Icon`，没有 clickable） | **有**：「越狱」`TextButton` `:397-402` | **无** |
| 是否受越狱模式禁用 | 是（越狱态既无倾斜也无水波） | 是 | 是 |
| 按下几何基准 | 大卡：同样 8°，四角位移绝对值最大 | 扁平卡：同样 8°，但卡矮 → 角点位移更小【推算：`h/2·sin8° ≈ 56dp/2×0.139 ≈ 3.9dp`，卡高按 72dp 内容测算也仅 ≈5dp】 | 同 H2 |

**①②③ 唯一本质不同的行为**：②里那行 `endActions` 的 TextButton 自带 `clickable`（`miuix:basic/Button.kt:60`、`:123` 均用独立 `interactionSource` + `LocalIndication`），按在"越狱"两个字上时，**按下事件被内层按钮消费**，因此出现的是按钮的 Sink/水波，而不是整卡的 Tilt；按在卡的其他位置则整卡 Tilt 并跳安装页。【依据 Compose 命中测试"最内层 clickable 消费 down 事件"推断，未实机逐帧验证——列为 §6 待测项】

**给还原者的提醒**：三处都写死 `pressFeedbackType = PressFeedbackType.Tilt`，而 `Card` 的默认值是 `None`、`showIndication` 默认 `false`（`miuix:basic/Card.kt:92-93`）。**不显式传这两行，hero 按下时什么反馈都没有**——这是本页最容易漏的两行。

## 3. 状态切换动画：定论 =「无过渡动画，直接替换」

**定论**：H1 / H2 / H3 之间切换**没有**任何过渡动画。既没有 `AnimatedContent` / `Crossfade` 包裹，也没有 `animate*AsState` 插值，`LazyColumn` 的 item 也没挂 `animateItem`。切换的瞬间：卡底色、卡高、圆角内所有内容、110dp 图标**全部一次性替换**。

**证据链（逐条可复跑）**

| 检查 | 结果 | 命令 / 出处 |
|---|---|---|
| 分支写法 | 裸 `when { ksuVersion != null -> … ; kernelVersion.isGKI() -> … ; else -> … }`，三个分支各自返回整棵子树 | `HomeMiuix.kt:250-433`（`when` 在 `:250`，三个分支起点 `:251` / `:372` / `:409`） |
| home 包内 animation 相关 import | **只有 6 行**：`AnimatedVisibility` + 4 个 enter/exit builder，**没有任何 `androidx.compose.animation.core` 引用** | `grep -rn "androidx.compose.animation" ui/screen/home/` → `HomeMiuix.kt:3-7`（`HomeMaterial.kt:3-7` 同样 5 行） |
| `AnimatedContent` / `Crossfade` | 全仓库仅 3 处，**都不在主页**：`ui/webui/WebUIActivity.kt:109`、`ui/screen/appprofile/AppProfileMaterial.kt:264`、`ui/component/AppIconImage.kt:70` | `grep -rn "AnimatedContent\|Crossfade" ui/` |
| `animate*AsState` | 全仓库 20+ 处，**home 包 0 处**（分布：module / modulerepo / install / colorpalette / kpm / executemoduleaction / appprofile） | `grep -rn "animate[A-Za-z]*AsState" ui/` |

| `animateItem` / `animateItemPlacement` | 全 `ui/` **0 命中**（`wc -l` = 0） | `grep -rn "animateItem" ui/ > /tmp/ai.txt; wc -l` |
| `animateContentSize` | home 包 0 命中 | 同上 |
| `graphicsLayer`（可用于手写过渡） | home 包 0 命中；`HomeMiuix.kt` 里唯一"变形"是静态 `offset(27.dp, 31.dp)` | `HomeMiuix.kt:294` |

1. **H1→H2 时卡高会跳变**：H1 的内容用 `Box` 叠了 110dp 图标 + 三行字，H2 是 `BasicComponent` 最小 56dp——高度差在切换瞬间直接跳，没有 `animateContentSize` 兜底。

1. **`fadeIn() / fadeOut() / expandVertically() / shrinkVertically()` 无参时的具体毫秒与弹簧**——未确证。

   - 影响：只知道"是库默认"，不能写死"220 ms / stiffness 之类"的具体数字。要落地时请按所用 Compose 版本自查，或直接显式传参。
2. **H2 里点「越狱」按钮不会触发整卡 Tilt**——依据 Compose 命中测试规则推断（内层 `clickable` 消费 down 事件），**未实机逐帧验证**。要确认需在真机上按住"越狱"二字观察整卡是否倾斜。
