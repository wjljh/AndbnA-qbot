# 70 · 二级页与导航

> 对象：SukiSU Ultra v4.2.1 的页面层级机制（`miuix-nav` 的 `NavDisplay` + 自家 `Navigator` 包装）。
> **一句话结论**：二级页用**库 `NavDisplay`**（miuix-nav 0.9.4，不是 androidx-navigation3 运行库），默认转场 = 从右滑入 + 下层视差 1/4 宽 + 暗幕 0.5，程序化时长 **500 ms**，手势/预测性返回走 **spring(dampingRatio = 1.0, stiffness = 146)**；**二级页不保留底部导航栏**（底栏只存在于 `Route.Main` 那一层）。

## 1. ① 导航机制：库 `NavDisplay` + 自家 `Navigator` 包装

### 1.1 分层事实（别被包名骗了）

| 层 | 是什么 | 出处 |
|---|---|---|
| 运行库 | `top.yukonga.miuix.kmp.nav.core.NavDisplay`（artifactId `miuix-nav-android:0.9.4`） | `MainActivity.kt:112-115`；`manager/gradle/libs.versions.toml:80`；`manager/app/build.gradle.kts:232` |
| 回退栈 | miuix 的 `NavBackStack`（`rememberNavBackStack<Route>(Route.Main)`） | `ui/navigation3/Navigator.kt:125-129`；`miuix nav/core/NavBackStack.kt:30-42` |
| 包装类 | SukiSU 自家 `Navigator`（push / replace / pop / popUntil / 结果总线），包名叫 `navigation3`，**与 androidx navigation3 无关** | `ui/navigation3/Navigator.kt:17-129` |

### 1.3 「tab」与「二级页」是两套机制

| 维度 | tab（主页/超级用户/模块/设置） | 二级页（About / AppProfile / Sulog / ModuleRepo…） |
|---|---|---|
| 机制 | `HorizontalPager`（4 页常驻，`beyondViewportPageCount = 3`） | `NavDisplay` 的 back stack entry |
| 状态 | 同层并列，滑动切换（`PagerNavigationSpringSpec`） | 压栈/出栈，带转场 |
| 底栏 | 有 | 无 |
| 出处 | `MainActivity.kt:402-435` | `:211-268` |

注：`Route.Home / SuperUser / Module / Settings`（`Routes.kt:26-40`）只是为了深链/快捷方式能落到某个 tab，它们的 entry 内容同样是 `mainScreenEntry()`（`MainActivity.kt:252-255`）——**不是二级页**。

### 1.4 跳转 API 与两个坑

- 跳转：`navigator.push(Route.AppProfile(group.uid))`（`ui/screen/superuser/SuperUserScreen.kt:67-68`）。
- 坑 1：`push` 是**幂等**的——栈里已有同值 key 时直接忽略（`Navigator.kt:28-32`）；需要多个实例就带唯一参数。
- 坑 2：返回值用 `navigateForResult` + `observeResult`，而 `setResult` 会**顺带 pop**（`Navigator.kt:80-99`）；`TemplateEditor` 的 `onBack` 就在用这套（`MainActivity.kt:217-226`）。

## 3. ③ 侧滑返回（`swipeDismiss`）

### 3.1 参数在哪、值是什么

```
val swipeDismiss = if (uiState.enableSwipeDismiss) {
    if (LTR) NavSwipeDirection.LeftToRight else NavSwipeDirection.RightToLeft
} else NavSwipeDirection.None                                  MainActivity.kt:192-200
entry<Route.X>(swipeDismiss = swipeDismiss) { ... }            :228-268（逐条都传）
```

| 项 | 值 | 出处 |
|---|---|---|
| 开关设置 | `enable_swipe_dismiss`，默认 **true** | `SettingsRepositoryImpl.kt:97-99`；`ui/screen/settings/SettingsUiState.kt:21` |
| 方向枚举 | `NavSwipeDirection.{None, LeftToRight, RightToLeft, TopToBottom, BottomToTop}` | `miuix nav/transition/NavTransition.kt:24-38` |
| LTR 默认方向 | `LeftToRight`（手指从左往右划 = 返回） | `MainActivity.kt:193-197` |
| RTL | `RightToLeft` | `:193-195` |
| 关闭时 | `None`（只能用顶栏返回/系统返回） | `:199` |
| 例外路由 | `Route.Flash`：`if (flashBackEnabled) swipeDismiss else None`（刷写中禁手势） | `:238-244` |

### 3.2 库侧怎么实现（关键：默认是关的）

- `NavTransition.dismissDirection` 默认 = `NavSwipeDirection.None`（`NavTransition.kt:81`）——**不传 `entry(swipeDismiss = ...)` 就没有侧滑**。
- 手势识别器挂在 **display 容器**上（不是顶层 entry），根页禁用（`enabled = topIndex > 0`）：`miuix nav/core/NavDisplay.kt:605-628`。
- 实际方向 = 该 entry 的 `swipeDismiss` 覆盖值，否则取 governing transition 的方向：`NavDisplay.kt:596-599`。
- 提交判定阈值（数值）：速度 `COMMIT_VELOCITY_THRESHOLD = 1.0`（进度单位/秒）、位置 `COMMIT_POSITION_THRESHOLD = 0.5`、手指最大进度 `MAX_FINGER_PROGRESS = 0.999`（`miuix nav/runtime/NavDriver.kt:111-122`）。
- 预测性返回：miuix-nav 自带 `PredictiveBackHandler`（`nav/gesture/PredictiveBackHandler.kt`），但 SukiSU 的系统级开关 `enable_predictive_back` 默认 **false**（`SettingsRepositoryImpl.kt:93-95`，只在 `KernelSUApplication.kt:53` 读取）。

## 4. ④ 进/退场动画（全部给数值）

### 4.1 几何：`NavTransitions.MiuixDefault`（全局默认，SukiSU 无逐路由覆盖）

| 阶段 | 位移 | 缩放 | alpha | 出处 |
|---|---|---|---|---|
| 进场（d 从 -1 到 0） | `translationX = +width -> 0`（整屏宽从**右**滑入；RTL 取反），并对齐到整像素避免边缘抖动 | 无 | 无 | `miuix nav/transition/NavTransitions.kt:47-52` |
| 被覆盖的下层（d 从 0 到 1） | `translationX = -0.25 x width`（向左视差 1/4 屏宽） | 无 | `1 -> 0.9`（`1f - 0.1f x coverProgress`） | `:52-56` |
| 退场 | 同一映射读 `d` 的反向 | 无 | 无 | `:11-27`（设计说明） |
| 圆角裁剪 | 滑入页四角按**系统屏幕圆角**裁（`cornerClipMode = Leading` 时只裁靠屏边的两角） | — | — | `MainActivity.kt:214`；`NavDisplayEffects.kt:63-66`；`NavDisplay.kt:882-900` |
| 暗幕 | 顶层之下铺全屏黑，最大 alpha **0.5** | — | — | `NavDisplayEffects.kt:67`；`NavDisplay.kt:703-734` |

### 4.2 时间曲线（三种相位，别混）

| 相位 | spec | 数值 | 出处 |
|---|---|---|---|
| 程序化 push/pop（点按钮进/退） | `NavSettleSpec.Tween` | **500 ms**，曲线 `NavProgrammaticEasing = NavSettleEasing(response = 0.8, damping = 0.95)`（欠阻尼弹簧阶跃响应烘焙成 easing：约 1/5 时长处已走完 48%，尾巴长而缓，全程不弹过 1） | `NavDriver.kt:96`；`NavMotion.kt:79-82`；`NavSettleEasing.kt:35-58`、`:66` |
| 手势释放-提交（预测性返回 / 侧滑完成） | `NavSettleSpec.Spring` | `spring(dampingRatio = 1.0, stiffness = 146, clampOvershoot = true)`，以释放速度作种子（并夹到不过冲下界） | `NavMotion.kt:76-79`；`NavDriver.kt:72`、`:82`、`:88`；`NavDisplay.kt:206-220` |
| 手势释放-取消 | `NavSettleSpec.Spring` | 同参数，静止点被钉为上界（不会越界到另一层） | `NavMotion.kt:78`、`:84-87` |

> 人话公式：**点进去 = 500 ms，曲线约等于「先快后慢」的 0.8 周期阻尼振荡积分（damping 0.95）**；**手滑一半松手 = 临界阻尼弹簧 damping 1.0 / stiffness 146（对「层」这一维，约 0.5 s 走完一个 entry）**。
> 注意：`stiffness = 146` 的单位是 **entry 序号轴**，不是像素（`NavDriver.kt:75-82` 注释）——照抄到像素位移上必须重新标定，别直接搬。

### 4.3 SukiSU 没用的两个预设（作者可能想要）

| 预设 | 效果 | 出处 |
|---|---|---|
| `NavTransitions.Modal` | 从**底部**升起（`translationY: +height -> 0`），下层保持可见（`opaqueDepth = 2f`）；配 `swipeDismiss = TopToBottom` 可下滑关闭 | `NavTransitions.kt:66-73` |
| `NavTransitions.None` | 无动画瞬间切换，且强制禁用侧滑 | `NavTransitions.kt:79-82` |

用法：`entry<Route.X>(transition = NavTransitions.Modal, swipeDismiss = NavSwipeDirection.TopToBottom) { ... }`（`NavDisplay.kt:132-152`）。

## 5. ⑤ 二级页保留底部导航栏吗——**不保留**

### 5.1 层级图（谁套谁）

```
MainActivity.setContent
└─ KernelSUTheme
   └─ Scaffold { navDisplay() }            <- 外层 Scaffold，无 bottomBar   MainActivity.kt:277
      └─ NavDisplay(backStack)             <- 22 个 entry 平级叠放        :212
         ├─ entry<Route.Main>  -> MainScreen()
         │    └─ Scaffold(bottomBar = { BottomBar(...) })                 :495-497
         │       └─ HorizontalPager { HomePager | SuperUserPager | ModulePager | SettingPager }
         └─ entry<Route.AppProfile> -> AppProfileScreenMiuix()
              └─ Scaffold(topBar = TopBar, popupHost = {})   <- 无 bottomBar   AppProfileMiuix.kt:104-121
```

### 5.2 结论与两条推论

1. **底栏只属于 `Route.Main` 这一层**，二级页是另一层全屏 entry，底栏自然消失（`MainActivity.kt:277` 的外层 Scaffold 没有 bottomBar）。
2. 二级页 `Scaffold` 只用 `topBar` + `popupHost` + `contentWindowInsets`（横向 inset），**没有 `bottomBar`**（`AppProfileMiuix.kt:104-121`、`AboutMiuix.kt:119-148`）。返回靠顶栏左键 / 系统返回 / 侧滑，**不靠底栏**。
3. 底部安全区由页面自己补：`Spacer(navigationBars.bottom + captionBar.bottom)`（`AppProfileMiuix.kt:160-165`）。

### 5.3 返回优先级（作者容易做错的一点）

| 场景 | 系统返回做什么 | 出处 |
|---|---|---|
| 栈深 > 1 | `navigator.pop()`（`TemplateEditor` 有结果回传特例） | `MainActivity.kt:215-227` |
| 栈深 == 1 且 `selectedPage != 0` | 先回到**第一个 tab**（主页），不退 App | `MainActivity.kt:503-521` |
| 栈深 == 1 且在第一 tab | 交给系统（退到后台） | 同上（`isBackEnabled = false`） |

## 6. ⑥ 给作者的最小改造路径（两方案对比 + 推荐）

### 6.1 你的现状（需求书 §5）

- 现有：4 个一级 tab 全在 `ui/App.kt`，**没有任何二级页**；「内容页 / Bot 页要看记忆」需要一层「点进去看详情」。
- 对照 SukiSU：tab 与二级页是两套机制（§1.3）；顶栏**不是共享的**——每页自带自己的 `TopAppBar`（`AppProfileMiuix.kt:500`、`SuperUserMiuix.kt:129`），所以「顶栏标题随页变」不一定要做全局标题栏，反而该让二级页自带顶栏。

### 6.2 方案 A：引入 `miuix-nav`（与 SukiSU 完全一致）

**要做什么**

1. 依赖：`implementation("top.yukonga.miuix.kmp:miuix-nav-android:0.9.4")`（SukiSU 的写法：`manager/gradle/libs.versions.toml:80` + `manager/app/build.gradle.kts:232`）。
2. 路由：`sealed interface Route : NavKey` 的 data object / data class，且必须 `@Serializable`（`Routes.kt:20-112`；库要求见 `NavBackStack.kt:30-42`，不可序列化会在状态恢复时抛 `SerializationException`）。
3. 回退栈：`rememberNavBackStack<Route>(Route.Main)` + 自己的 `Navigator`（`Navigator.kt:125-129` 只有 5 行，可直接照结构）。
4. 宿主：`Scaffold { NavDisplay(backStack, effects = NavDisplayEffects(cornerClipRadius = rememberNavSystemCornerRadius()), onBack = { navigator.pop() }) { entry<...> } }`（`MainActivity.kt:212-270`）。

**代价（实测 POM）**：会拉入 `navigationevent-compose-android:1.1.2`、`kotlinx-serialization-json:1.11.0`、`kotlinx-collections-immutable:0.5.1`、`lifecycle-*:2.11.0`、`miuix-squircle-android:0.9.4`（来源：`miuix-nav-android-0.9.4.pom`）。你工程若已在用 Miuix 0.9.4，版本天然对齐。

**白拿的能力**：侧滑返回 + 预测性返回、系统圆角裁剪、暗幕、每 entry 的 `rememberSaveable` / `ViewModel` 隔离、进程重建后恢复栈。

### 6.3 方案 B：自建 state 栈 + `AnimatedContent`（不加依赖）

```
sealed interface Screen { data object Main : Screen; data class Memory(val botId: String) : Screen }
var stack by rememberSaveable(...) { mutableStateOf(listOf<Screen>(Screen.Main)) }
BackHandler(enabled = stack.size > 1) { stack = stack.dropLast(1) }
AnimatedContent(targetState = stack.last(), transitionSpec = {
    (slideInHorizontally(tween(500)) { it } + fadeIn(tween(500))) togetherWith
    (slideOutHorizontally(tween(500)) { -it / 4 } + fadeOut(tween(500)))
}) { screen -> when (screen) { ... } }
```

**移植自 SukiSU 的数值**（照搬 `NavTransitions.MiuixDefault` 的几何）：进场从 `+width` 到 0；下层视差 `-0.25 x width`；alpha 只做 `1 -> 0.9`（**不是**淡出到 0）；暗幕 `0.5` 黑。时长用 **500 ms**，曲线用 `tween(500)` + 等效缓动（response 0.8 / damping 0.95 的阶跃响应），**不要**直接搬 `spring(stiffness = 146)`（单位是 entry 轴，像素上会过快）。

**要自己补的**：侧滑返回（可选，`detectHorizontalDragGestures` + `Animatable`）、预测性返回（Android 13+ 的 `OnBackInvokedCallback`；SukiSU 自己默认也是关的）、`rememberSaveable` 栈（进程重建）、每页状态隔离。

### 6.4 对比与推荐

| 维度 | A `miuix-nav` | B 自建栈 + `AnimatedContent` |
|---|---|---|
| 改动量 | 依赖 1 行 + 路由类 + 宿主替换（约 200 行级） | 1 个 sealed class + 栈 + `AnimatedContent`（约 60-100 行） |
| 新增依赖 | 5 个传递依赖（含 serialization、navigationevent） | **0** |
| 观感与 SukiSU | **逐帧一致**（同一份 `NavTransitions` 代码） | 几何可照抄，曲线需自调 |
| 侧滑返回 / 预测性返回 | 自带 | 自己做或不做 |
| 系统圆角裁剪 + 暗幕 | 自带（`NavDisplayEffects`） | 自己做（squircle 裁剪不公开，只能 `RoundedCornerShape` 近似） |
| 状态恢复 | 自带（`NavSaveableStateHolder`） | 自己做 |
| 调试成本 | 栈 / 生命周期由库管，出错信息较隐晦 | 全在自己手里 |

**推荐**：
- **只做「内容页 / Bot 页 -> 记忆页」这一层（1 个二级页）**：走 **方案 B**。收益/成本比最高，60 行就能落地，几何数值本文已给全；先抄对「从右滑入 + 下层视差 1/4 + 暗幕 0.5 + 500 ms」，观感已接近原生。
