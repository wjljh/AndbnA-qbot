## 1. 三十秒结论

1. **设置页没有组标题，一个都没有**——不是"没找到"，是结构上就不存在这个位置（§2.0 给证据）。但库里**有** `SmallTitle`，SukiSU 在**别的页**用过（§2.0 末尾给规格，你要加可以直接抄）。
2. **三种行全部来自 `miuix-preference` 库**，SukiSU 一行自绘的都没有；不接这个库 = 要自己复刻约 **11 项数值 + 1 层叠层动画 + 1 个弹层**（清单见 §7.2）。
3. **禁用态只有一条主色 `disabledOnSecondaryVariant` #B2B2B2**，但它**只管标题/副标题/箭头/值文字**；行首图标库不管，SukiSU 只在 4 处手动切了、其余没切（§4.3 有个一致性坑，照抄时统一掉）。
4. **点击叠层是整行矩形，画在文字之上，并且四角会被卡片的 16dp 圆角切掉**（§6，这条是 90 §7.5 的补正）。

## 4. 禁用态（整行变灰：用哪个变量、哪些东西会变）

### 4.1 唯一的"变灰"变量

| 元素 | 变量 | 浅色字面值 | 出处 |
|---|---|---|---|
| 标题 | `disabledOnSecondaryVariant` | **#B2B2B2** | `[L]basic/Component.kt:274`、`[L]theme/Colors.kt:364` |
| 副标题 | `disabledOnSecondaryVariant` | #B2B2B2 | `[L]basic/Component.kt:288`、同上 |
| 行尾箭头（Arrow） | `disabledOnSecondaryVariant` | #B2B2B2 | `[L]preference/ArrowPreference.kt:120` |
| 值文字 + 上下箭头 | `disabledOnSecondaryVariant` | #B2B2B2 | `[L]preference/OverlayDropdownPreference.kt:149-153` |
| Switch（开） | `disabledPrimary` / `disabledOnPrimary` | #C2D9FF / #F3F8FF | `[L]basic/Switch.kt:237`、`[L]theme/Colors.kt:350-351` |
| Switch（关） | `disabledSecondary` / `disabledOnSecondary` | #F0F0F0 / #FCFCFC | `[L]basic/Switch.kt:238`、`[L]theme/Colors.kt:361-362` |

> `disabledOnSecondaryVariant` 在**浅色 #B2B2B2 / 深色 #707170**（暗色块见 `[L]theme/Colors.kt`，90 §7.2 已列）。

### 4.2 禁用会连带发生的三件事

1. **不可点**：`clickable` 只在 `enabled && onClick != null` 时挂上（`[L]basic/Component.kt:146-157`）；`OverlayDropdownPreference` 连展开回调都不走（`:157-163`）。
2. **不触发触感**：开关的 `toggleable` 传 `enabled = false`（`[L]basic/Switch.kt:127`），滑块也不再可拖（`:167-171`）。
3. **不发叠层**：没有 `clickable` 就没有 interactionSource 按压事件，MiuixIndication 收不到 `Press`（`[L]utils/MiuixIndication.kt:102-105`）→ 按下去毫无变化。

### 4.3 SukiSU 的两套写法（**第二个是坑**）

- **写法一（主流）：直接不渲染**。`KsuIsValid { … }` 包住整卡，内核版本拿不到就整块消失（`[S]ui/component/KsuValidCheck.kt:7-16`）；`isKpmAvailable`、`isSusfsSupported` 同理（`:283`、`:308`）。`SettingsMiuix.kt` 里有 4 个 `KsuIsValid` 块（`:137`、`:224`、`:307`、`:491`）。
- **写法二：`enabled = false` 变灰**。只有 9 处，全部按"功能是否 supported"切换：

| 行 | 条件 | 位置 |
|---|---|---|
| SU 兼容模式（下拉） | `suCompatStatus == "supported"` | `:361` |
| 内核 umount（开关） | `kernelUmountStatus == "supported"` | `:383` |
| SELinux 隐藏（开关） | `selinuxHideStatus == "supported"` | `:405` |
| sulog（开关） | `sulogStatus == "supported"` | `:427` |
| ADB root（开关） | `adbRootStatus == "supported"` | `:449` |
| shell su 仅 ADB（开关） | `shellSuAdbOnlyStatus == "supported"` | `:471` |
| 软重启（开关） | `!isLateLoadMode` | `:486` |
| 自动越狱（开关） | `isLateLoadMode` | `:537` |
| 卸载（箭头行） | `!isLateLoadMode` | `:553` |

- **坑（照抄时请统一）**：`BasicComponent` **不会**帮你把行首图标变灰。SukiSU 只在 4 处手动切了 tint：`:424`（sulog）、`:468`（shell su）、`:483`（软重启）、`:534`（自动越狱）；其余禁用行（`:361`、`:383`、`:405`、`:449`、`:553`）的图标仍是 `onBackground` 全黑 → **同一页里"灰标题 + 黑图标"并存**。
  > 你的实现里请统一：`tint = if (enabled) colorScheme.onBackground else colorScheme.disabledOnSecondaryVariant`，和文字同一条规则。
- **文案联动**：功能不支持时副标题会整句换成 `feature_status_unsupported_summary` / `_managed_` / `_forced_`（`:344-348`、`:376-380`、`:388-392`、`:409-413`、`:441-445`、`:462-466`、`:518-522`、`:528-532`）——即**灰行还要带一句"为什么不支持"**，不是只变灰。

## 6. 点击反馈：`MiuixIndication` 叠层在设置行上的**位置**与**裁切**

90 §7.5 已经把"是什么"定性完了（矩形叠层、+0.10、spring 数值）。这里只补它缺的两问。

### 6.1 位置：铺满整行（含 16dp 内边距），边到边

- 行的修饰符链是 `heightIn(min 56dp) → fillMaxWidth → clickable(...) → padding(16dp)`（`[L]basic/Component.kt:159-164`，顺序即由外到内）。
  **`clickable` 排在 `padding` 之前**，所以叠层节点的尺寸 = **整行**（宽度 = 卡片内容宽 = 屏宽 − 2×12dp；高度 = 该行带），而不是"文字区"。
- 叠层画在**内容之上**：`drawContent()` 之后才 `drawRect(color, alpha, size = size)`（`[L]utils/MiuixIndication.kt:129-133`）→ 按下时**文字、图标、开关一起被蒙一层 10% `onBackground`**，不是只蒙底。
- 因此视觉上是"整块行被压暗"，行与行之间**不会**互相渗透（每行各自一个节点、各自 `size`）。

### 6.2 裁切：**会**被卡片 16dp 圆角切掉（补正 90 §7.5）

- `Card` 用的是 `squircleSurface`（`[L]basic/Card.kt:177`），它内部走 `squircleShaderMask`：把内容画进一个 Offscreen 图层，再用 **DstIn 抠掉四角**（`[L]squircle/SquircleBackground.kt:255-278`；`:281-288` 的 `drawSquircleFast` 即"填色 → drawContent → maskSquircleCorners"）。
- 结论：**第一行的左上/右上、最后一行的左下/右下，在 16dp 半径之外的部分会被抠掉**；中间行的叠层则是完整矩形（上下左右都碰不到圆角）。
- 也就是说：卡片**有**形状裁剪（内容级），只是**叠层自己**是矩形、不带自己的圆角。90 §7.5 表格里那句"矩形、无圆角裁剪"应读作"叠层不自带圆角"，**不是"不会被卡片的圆角打掉"**——勘误见 §8。

### 6.3 数值（可直接抄）

| 参数 | 值 | 出处 |
|---|---|---|
| 按下叠加 alpha | **+0.10**（按住状态也是 +0.10，不叠加成 0.20） | `[L]utils/MiuixIndication.kt:27-28`、`:66-73` |
| 悬停 / 聚焦 | +0.06 / +0.08（手机端无意义，触屏走 press） | `:25-26` |
| 叠层色 | `colorScheme.onBackground` **#000000** | `[L]theme/MiuixTheme.kt:32`、`[L]theme/Colors.kt:373` |
| 进（按下）动画 | `spring(damping = 1.0, stiffness ≈ 987)`（源码 `folmeSpring(damping = 1.0, response = 0.2)`，response 0.2s → (2π/0.2)² ≈ 987） | `[L]utils/MiuixIndication.kt:30`、`[L]anim/MiuixEasing.kt:24-26` |
| 出（抬起）动画 | `spring(damping = 0.95, stiffness ≈ 322)`（`response = 0.35` → (2π/0.35)² ≈ 322） | `[L]utils/MiuixIndication.kt:31`、同上 |
| 形状 | 矩形 `drawRect`，无扩散、无位移、无缩放 | `:133` |

### 6.4 一个容易漏的细节：点开关本体时是**另一层**叠层

- `Switch` 自己有 `Modifier.toggleable(...)`（`[L]basic/Switch.kt:119-130`，不传 indication → 落回 `LocalIndication`，即同一个 MiuixIndication），而外层 Box 已经 `.clip(CircleShape)` 成 49×28 胶囊（`:143-144`）。
- 结果：**手指落在开关上时，是 49×28 胶囊内的一层叠层**；手指落在行上其它位置时，才是整行矩形叠层。两者不会叠加（子节点吃掉按压事件，父节点 interactionSource 收不到 Press）——后半句是按 Compose 事件分配推导，未真机核。

> **未真机实测声明**：本节位置/裁切全部由"修饰符链 + 形状遮罩"推导（本机无 SukiSU 运行环境）。数值部分均来自源码，可直接照抄；"看起来对不对"建议你装上真机后只看一处——第一行按下时四角是否跟着圆角走。
