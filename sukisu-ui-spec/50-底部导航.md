# 50 · 底部导航（Bottom Bar）

> **一句话结论**：SukiSU Ultra v4.2.1 默认用的是 **停靠式 `NavigationBar`**（库默认 5 个参数里只覆盖了 `color`，标签 **12 sp** / 条目高 **64 dp** / 图标 **26 dp** / 分隔线默认开）；液态玻璃 `FloatingBottomBar` 是**出厂关闭的可选项**（标签写死 **11 sp**），也是唯一有「胶囊指示器」的分支。
> 上游 `00-总览.md` §4.4 C10/C11 与本册一致，**不是勘误**——11 sp 与 12 sp 是两套实现各自的取值，见 §4。

## 1. 两种实现与启用条件

### 1.1 判定链（从设置到渲染）

```
SettingsRepositoryImpl.enableFloatingBottomBar   prefs.getBoolean(..., false)          :109-111
  -> MainActivityViewModel.uiState.enableFloatingBottomBar                           :50-51
  -> CompositionLocalProvider(LocalEnableFloatingBottomBar provides ...)             ui/MainActivity.kt:183
  -> BottomBarMiuix: val enableFloatingBottomBar = LocalEnableFloatingBottomBar.current  :54
  -> if (!enableFloatingBottomBar) { 停靠式 } else { 液态玻璃 }                       :63 / :84
```

- `LocalEnableFloatingBottomBar` 的**默认值就是 false**：`ui/theme/Theme.kt:137`（`staticCompositionLocalOf { false }`）；`LocalEnableFloatingBottomBarBlur` 同样 false（`:139`）。
- 持久化默认值也是 false：`enable_floating_bottom_bar` = false（`SettingsRepositoryImpl.kt:110`）、`enable_floating_bottom_bar_blur` = false（`:114`）。
- 所以**出厂 = 停靠式、无模糊**，与需求书 §4.5「是停靠式还是悬浮式」的答案一致：**停靠式**。

### 1.2 三条互斥分支

| 分支 | 条件 | 组件 | 出处 |
|---|---|---|---|
| A 停靠底栏（默认） | `!enableFloatingBottomBar` | `BlurredBar` -> `NavigationBar` | `BottomBarMiuix.kt:63-83` |

## 4. 库几何常量 + **标签字号 12 sp 的定论**

```
NavigationBarDefaults（miuix 0.9.4, basic/NavigationBar.kt:440-482）
  ItemHeight             = 64.dp     :442
  IconSize               = 26.dp     :445
  LabelFontSize          = 12.sp     :448   <- 停靠栏标签 = 12 sp（定论）
  IconTopPadding         = 8.dp      :451
  BottomPadding          = 8.dp      :454
  SelectedPressedAlpha   = 0.5f      :457
  UnselectedPressedAlpha = 0.6f      :460
  UnselectedAlpha        = 0.4f      :463
```

### 4.1 为什么会出现「11 sp 还是 12 sp」两种说法

| 分支 | 标签字号 | 行高 | 出处 | 归谁 |
|---|---|---|---|---|
| 停靠式 `NavigationBar` | **12 sp** | 未指定（字体度量） | `NavigationBar.kt:448`（全项目仅此一处定义） | miuix 库 |
| 液态玻璃 `FloatingBottomBar` | **11 sp** | **14 sp** | `BottomBarMiuix.kt:121-128`（SukiSU 在 `Text` 上写死） | SukiSU 自家 |

**定论**：需求书 §2 G2 说的「上次两处说法不一致」，**不是同一元素的两个错误取值，而是两个不同实现各自的取值**。照抄时按这个规则选：
- 做**停靠栏** -> 标签 **12 sp**、条目高 64 dp、图标 26 dp（库自动给，除非你要改）；
- 做**液态玻璃浮层** -> 标签 **11 sp / 行高 14 sp**，且必须自己写 `Text`（`FloatingBottomBar` 的自定义 `content` 只给图标槽位，文字由调用方提供，`BottomBarMiuix.kt:100-129`）。

### 4.2 勘误检查（按硬性要求 5 逐条核）

| 上游文档 | 写法 | 与源码是否一致 | 处理 |
|---|---|---|---|
| `00-总览.md:204` | 「11 sp ｜ 2 处 ｜ 浮层底栏 label（行高 14 sp）」 | **一致**（浮层确实 11 sp，且归属写明「浮层」） | 无需勘误 |
| `00-总览.md:353`（C11） | 「11 sp 只在浮层实现里写死；停靠式由库给 12 sp。两者不一致是源码现状，不是笔误」 | **一致**，判断正确 | 无需勘误 |
| `00-总览.md:269` | 停靠底栏 条目高 64 / 图标上间距 8 / 文字下边距 8 | 一致 | 无需勘误 |
| `00-总览.md:327` | 停靠底栏图标 26 dp | 一致 | 无需勘误 |
| `00-总览.md:352`（C10） | 选中 = 颜色 + Bold，无 indicator | 一致 | 无需勘误 |
| `90-组件库.md:53` | 底栏细节「见 50-底部导航.md」（占位引用） | 一致（本册即该引用目标） | 本册补齐 |

## 5. 角标（Badge）——与 80-角标与按钮 的分工

> 本节给**位置与传递方式**；尺寸/颜色成表留给 `80-角标与按钮.md`。若 80 已交付以 80 为准；本节数值与 80 同源 `miuix basic/Badge.kt`，不会冲突。

### 5.1 怎么传

```
NavigationBarItem(..., badge = navigationBadgeFor(index, navigationBadge))    BottomBarMiuix.kt:78
navigationBadgeFor(...): (@Composable () -> Unit)? = { Badge { Text(count.toString()) } }   :145-171
```

- `badge` 是 `(@Composable () -> Unit)?`，为 `null` 时不占位（`NavigationBar.kt:153`）。
- 库把图标包进 `BadgedBox`：`NavigationItemIcon` -> `BadgedBox(modifier, badge = { badge?.invoke() }) { content(Modifier) }`（`:430-437`）。
- badge 存在时 item 额外加 `Modifier.badgeBounds()`，把角标**钳制在条目边界内**（`:175`；`Badge.kt:238-251`）。

### 5.2 位置

角标锚在**图标右上角**（不是条目右上角）：`BadgedBox` 先量 anchor（图标）再算偏移——`badgeX = anchorWidth - offset`、`badgeY = -badgeHeight + offset`，并被 `BadgeEndRuler/BadgeTopRuler`（= 条目边界）夹住（`Badge.kt:99-114`、`:238-251`）。注释原文「anchors to the icon top-end corner」（`:423-428`）。

### 5.3 尺寸 / 颜色（基础值）

| 项 | 有内容（数字） | 无内容（纯点） | 出处 |
|---|---|---|---|
| 直径/最小宽高 | `LargeSize = 16.dp`（`defaultMinSize`） | `Size = 6.dp` | `Badge.kt:139`、`:182-185` |
| 文字 | `footnote2` = **11 sp**，行高强制 **16 sp**、居中 | — | `:163-169`（`footnote2` 11 sp 见 `00-总览.md:164`） |
| 水平内距（>9 时） | `4.dp` | — | `:220` |

## 6. 底栏高度与 `Scaffold` 的关系（主页尾部 Spacer 的唯一依据）

### 6.1 高度公式（停靠式）

```
底栏实测高 = 0.75 dp（分隔线） + 64 dp（条目高） + navigationBars.bottom inset
             (+ animatedCaptionBarHeight，仅 captionBar inset > 0 时，tween 300ms)
```

- 分隔线在 `Column` 内、条目之上：`NavigationBar.kt:90-97`（thickness `0.75 dp`，`Divider.kt:71`）。
- 条目行固定 `64 dp`：`NavigationBar.kt:165`、`:442`。
- inset Spacer 高度 = `navigationBars` 底 + 动画中的 captionBar：`:109-128`。
- 【推算】手势导航（inset 约 24 dp）-> 约 **88.75 dp**；三键导航（inset 约 48 dp）-> 约 **112.75 dp**。示例值仅供参考，实际以设备 inset 为准。

### 6.2 这个高度如何变成 `innerPadding.bottom`

```
MainScreen: Scaffold(bottomBar = bottomBar) { innerPadding ->
                pagerContent(innerPadding.calculateBottomPadding()) }   ui/MainActivity.kt:495-497
miuix Scaffold: bottom = if (isBottomBarEmpty) insets.calculateBottomPadding()
                       else bottomBarPlaceable.height.toDp()             miuix basic/Scaffold.kt:333-338
```

即：因为有 bottomBar，`innerPadding.bottom` **精确等于底栏实测高度**（不含额外常量）。

### 6.3 传给页面之后

- `pagerContent(bottomInnerPadding: Dp)` -> 四个 pager 各收一份（`ui/MainActivity.kt:400`、`:430-433`）。
- 主页唯一用途是尾部 Spacer：`Spacer(Modifier.height(bottomInnerPadding + if (!Natives.isFullFeatured()) navigationBars.bottom else 0.dp))`（`ui/screen/home/HomeMiuix.kt:179-184`）。
  - **有底栏时**：等于底栏高度（inset 已含在底栏内，不重复加）；
  - **无底栏时**（非 full-featured）：补一遍系统导航栏 inset。
- 其余页同样用它做列表尾部占位：`SuperUserMiuix.kt:480-482`（主列表）、`:392-394`（搜索态取 `maxOf(bottomInnerPadding, imeBottomPadding)`）。

### 6.4 浮层分支的高度

`FloatingBottomBar` 总高 = 内容行 `64 dp` + 外层 `padding(bottom = 8.dp + navigationBars inset，无 inset 时 28.dp)`（`BottomBarMiuix.kt:85-92`、`FloatingBottomBar.kt:388`），横向 `start/end 28.dp`（`:92`）。这个「悬空 + 外边距」高度同样被 `Scaffold` 全额计入 `innerPadding.bottom`（`Scaffold.kt:333-338`）——浮层模式下内容底部会多留一段，是本实现的已知代价。
